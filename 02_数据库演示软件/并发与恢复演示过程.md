# 模拟作答、并发写入与数据恢复演示过程

本软件使用本机 SQLite 演示库。日常操作和下面的交互测试写入当前 Windows 用户的 `%LOCALAPPDATA%\MathDifficultyDemo\math_learning_demo.db`；随软件附带的匿名初始数据库用于“恢复初始演示数据”。

## 一、在首页批量生成模拟作答

1. 在首页选择要生成的作答条数，然后点击“随机生成模拟作答”。
2. 程序从当前学习者与演示题目中随机选择组合，随机标记“会”或“不会”。如果当前没有学习者，先创建匿名模拟学习者。
3. 同一学习者第一次回答某题记为 `practice`；再次回答该题记为 `review`。每条作答使用不同的 `event_id`。
4. 整批插入放在一个数据库事务中：全部成功才提交，任何一步出错就整体回滚。插入后由触发器更新个人最新状态；首次作答视图和题目难度视图据此重新计算。
5. 首页刷新学习者逐题列表和人数、题数、作答记录等指标，并显示本次实际新增的条数。

演示题库包含现有三个章节的完整题号范围：`660s1` 第 1 章 1～19 题、第 2 章 20～38 题，`bluefriend27s1` 第 1 章 1～16 题，共 54 道题号。

## 二、两条不同作答同时提交

入口：左侧“并发与备份恢复” → “同时提交两条作答”。

1. 程序新建一名匿名测试学习者，准备针对同一道演示题的两条**不同**作答：不同 `event_id`、不同自评结果；两条的 `answered_at` 有明确先后。
2. 两个线程各自打开 SQLite 连接，用 `Barrier(2)` 等齐后同时尝试写入。界面记录每条请求从开始等待、获得写锁到提交的情况。
3. SQLite 的 `BEGIN IMMEDIATE` 让两个写事务依次取得写锁。演示特意让作答时间较晚的复习事件先取得锁，并短暂停留；作答时间较早的练习事件等待锁释放后再提交。这样可以直接看到排队时间。
4. 两条事件编号不同，因此都应保存。查询各自的事件编号，核对两条都恰好出现一次，并显示实际获得锁的顺序、等待时间和提交结果。
5. 触发器依据 `answered_at` 更新该学习者的最新状态。这里复习事件先提交、较早的练习事件后提交，但较早的作答不能覆盖较晚的个人状态；首次作答仍只计时间最早的练习事件。

这个测试的重点是**两条不同数据都成功写入，以及写入冲突时的排队与最终状态**。相同 `event_id` 的重试去重仍由数据层处理，但不是本页并发演示的主场景。

## 三、选择一条作答，删除后恢复

入口：左侧“并发与备份恢复” → 在作答列表中选择一条记录 → “删除所选记录” → “从备份恢复”。

1. 删除前，程序用 SQLite `backup()` API 为当前工作库建立一份备份，记录六张表各自的行数和内容 SHA-256 摘要。
2. 程序开启写事务。由于逐题进度可能引用所选事件，先处理对应学习者和题目的进度，再删除选中的 `answer_events` 行，并根据剩余事件重算该题的最新状态；最后提交。
3. 界面展示被删除的事件编号、删除前后的作答条数，以及该学习者该题的状态变化。此时可以看到事件确实已不在工作库中。
4. 点击“从备份恢复”，程序把备份还原为当前工作库，重新读取六张表的行数与 SHA-256 摘要。
5. 只有在恢复后的内容与备份前一致、`PRAGMA quick_check` 返回 `ok`、`PRAGMA foreign_key_check` 没有错误，并且被选事件重新出现时，界面才显示恢复通过。

备份文件保存在本地演示数据目录，供这次交互恢复使用；随软件附带的初始样例库不参与删除。
